# Adreno OpenCL build

The Android OpenCL experiment keeps the existing UI, Pi/session/tool loop and native llama.cpp bridge. It uses upstream llama.cpp `1a24df163920a4744a95373d178d790b72a9bb2f` plus Qualcomm PR [30999](https://github.com/ggml-org/llama.cpp/pull/30999), pinned to `0c50cc146ac66155afdc219ef9004edafd5defb0`. The nine changed OpenCL files were compared with that pinned PR head. The patch is already applied and recorded in `patches/qualcomm-q2k-30999.patch`.

PR 30266, merged in upstream on 2026-10-11, supplies the 512-dimensional Gemma 4 attention path used by this architecture. Q2_K support is needed by 36 tensors in the selected dynamic-quantization GGUF; this vendored snapshot carries that patch; upstream status may change. This source inclusion alone is not device verification.

Set `BOLT_OPENCL=1 BOLT_VULKAN=0`, `OPENCL_INCLUDE_DIR` to a pinned Khronos OpenCL-Headers checkout, and `OPENCL_LIBRARY` to an Android ARM64 OpenCL library used for linking. The verification environment uses OpenCL-Headers `82f60316cc142e7b21dc1d8983b26de18858fbd9`. It links against a private copy of the target device's vendor `libOpenCL.so`. This vendor library is never copied into the app or source export; runtime uses the system vendor library via Android's `uses-native-library` declaration.

`tools/bolt/prebuild.mjs android` adds the optional `libOpenCL.so` manifest declaration. Compiled OpenCL programs are cached under the application's private cache directory. First initialization may compile kernels; later runs may use that cache. Inference uses F16 KV, 16384 context tokens, batch 256, microbatch 256, six CPU threads and requests GPU offload. The initial project workspace request alone used about 7500 tokens with the full Pi tool/Skill catalog, so the earlier 8192-token experiment left too little room for live tool results. Both the Pi model declaration and native allocation now use 16384. Confirm actual GPU operations and any CPU fallback in the native logs and device measurements.

The Vulkan patch and compatibility documentation remain as an alternative for comparison. They do not execute in an OpenCL-only build. iOS continues to compile the Metal path.

## Galaxy S25 compatibility

The stock S25 driver is OpenCL 3.0 QUALCOMM build 0800.64.7, Compiler E031.47.18.50. The tiled Q4_K vocabulary projection produced incorrect logits for the selected model at K=2560, M=262144, N=1. CPU/OpenCL layer traces localized the large error to this projection. Disabling only `GGML_OPENCL_Q4K_GEMV_TILED` restored the fixed arithmetic answer on both 20-token and 425-token inputs, with Flash Attention still enabled.

The noshuffle large-M GEMM also failed the independent N=2 regression. This tree therefore defaults Adreno 830 Q4_K vocabulary weights (at least 32768 rows) to the generic flat layout for both conversion and dispatch. The projection still runs on the OpenCL GPU. Other Adreno kernels remain enabled. `GGML_OPENCL_Q4K_GEMV_TILED=1` can deliberately reproduce the old route for diagnostics; it is not a recommended setting on this device. The related upstream [PR 30412](https://github.com/ggml-org/llama.cpp/pull/30412) addresses the multi-row tiled output-head case, whereas this S25 also failed at N=1. That PR is not included here.

The native matrix probe accepts up to 65536 output rows and 128M weight elements, allowing seeded Q4_K tests at the 32768-row routing threshold against an independent CPU dequantization/FP64 dot-product reference. Passing small matrices does not verify this large-vocabulary route. Full Pi prompts, multi-turn answers and physical-device recording must also be checked.

Android events include a total-PSS snapshot at model load and turn completion. The UI labels this `PSS`; native VmRSS remains a separate counter. External `dumpsys meminfo` sampling supplies observed peaks including graphics allocations. Do not add graphics PSS to total PSS or treat the CPU mapping's VmRSS as total on-device model memory.

The shared chat execution panel opens while a run is active and can be collapsed without stopping the run. Its expanded body stays 220 logical pixels tall with nested scrolling; new steps follow the bottom unless the user scrolls back. The header retains the elapsed time and a separate Stop action. Completed runs start collapsed and use the same fixed-height viewport when expanded. It displays existing public progress updates, tool activity and context-compaction events; private reasoning is not rendered. Pi sessions, tools and automatic compaction are unchanged.

Native inference additionally reports queueing, initial model loading, prompt preparation and output generation in that panel. The preparation bar uses actual native batch counters, excluding reused KV-prefix tokens from its denominator. Each tool round starts a fresh preparation count. A 100% submitted prompt remains in the preparation state until the first output token arrives; the bar is a token counter rather than a time estimate. Progress is scoped to the Pi session and request tag and removed on success, cancellation or failure. Thinking remains off for this model configuration, so output-token counts and public tool updates do not represent a reasoning stream.

## Persistent fixed-prefix cache

Android stores at most two 512 MiB fixed-prefix checkpoints in the app-private, backup-excluded `noBackupFilesDir/llama-prefix-cache` directory. These are not included in the source export or recordings. The prefix ends before the first user message: the native chat template is rendered with two different user sentinels and compared token-for-token against the real request. User messages, assistant history and tool results are never written to this disk cache. In-process exact-prefix reuse remains preferred for an appended conversation.

Each checkpoint is bound to a SHA-256 digest of the model, native sources/backend/compiler, context and inference configuration, Android build fingerprint, and exact prefix tokens. The model digest is indexed by file identity/size/modification information to avoid rehashing the full weights on every launch. Checkpoints use llama.cpp's full state save/load API, with atomic temporary-file commits and a separate SHA-256 integrity check before deserialization. Restored token IDs must also exactly match. A missing, invalid, incompatible or oversized cache falls back to ordinary preparation; model weight loading and new user/tool tokens are still required. Cache files survived same-APK process restarts in the S25 test; compatible APK updates are a design capability that still needs upgrade validation; clearing app data or uninstalling removes them.

For sliding-window attention, rollback after local-attention entries were discarded uses a fixed-prefix checkpoint instead of pretending that all prior KV cells remain available. Disk restoration has its own UI state and `prefix_cache_restored` event; `begin.cache_origin` distinguishes `disk`, `memory` and `none`. `cache_prompt:false` bypasses both disk and memory reuse. Run `python3 tools/bolt/test_prefix_cache.py` for host integrity tests; real model correctness and restart performance must be verified on the target device before reporting this as accepted.
