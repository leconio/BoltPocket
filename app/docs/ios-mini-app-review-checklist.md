# iOS 小程序提审门禁

更新日期：2026-08-21

当前结论：**正式 App Store 提交被外部状态阻断**。TestFlight 内部验证不代表获准正式发布。

## 代码已完成

- [x] 小程序仅运行项目内、源码可见、不可变内容快照；远程脚本、iframe、弹窗、下载和顶层外跳被禁用。
- [x] `boltpocket.h5.json` schema 3 逐项声明设备能力、具体用途、固定单次/会话范围、外部数据接收方和精确网络 origin。
- [x] 项目列表、历史列表和预览菜单均提供“权限与数据”，授权前展示能力名称、用途、范围、接收方与拒绝影响。
- [x] 单次能力每次操作询问；会话能力仅绑定 task ID 与内容 SHA-256。拒绝后本次预览不重复提示，用户可主动重置。
- [x] 切换、关闭、退到后台或内容变化会取消待处理请求、撤销授权，并停止位置监听、媒体轨道、常亮、振动、全屏和画中画。
- [x] 联网默认关闭；用户同意前不创建 WebView，同意后 CSP 只开放清单中的精确 HTTPS/WSS origin。
- [x] 小程序仅由当前用户在自己的本机项目中创建或导入；不提供发布、分享、目录、搜索、下载、交易或面向其他用户的分发入口。

## 提交前必须完成

- [ ] 通过 App Store Connect/Apple Developer Support 提交原生 API 暴露说明，取得 Apple 对 Guideline 4.7.2 的书面事先许可。
- [ ] 将许可 case ID、批准日期和原始回执归档后，才把 `APPLE_MINI_APP_NATIVE_API_APPROVAL` 改为 `approved`；不得先写占位值。
- [ ] 在 Review Notes 说明：小程序是用户本人创建或导入的私人本机项目内容，不设目录且不能发布、分享或变现；列出全部 18 项标准 Web API 到宿主能力的映射，以及逐次同意和撤销路径。
- [ ] 请 Apple 书面确认：在上述无分发架构下，4.7.1、4.7.4 与 4.7.5 的软件目录治理要求是否不适用；在得到相反答复前，不为过审虚构 Universal Link、年龄分级或举报审核流程。
- [ ] 在干净 iPhone 上逐项验证允许、拒绝、不重复提示、主动重置、系统二次授权、后台/退出清理和内容哈希变化失效。
- [ ] 核对 App Privacy、隐私政策、个人信息收集清单、第三方共享清单和系统权限清单与最终二进制及网络抓包一致。

`pnpm release:check` 会在 Apple 4.7.2 许可未归档时失败关闭。该门禁不应为了生成 TestFlight 验证包而伪造通过。
