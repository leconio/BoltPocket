# `@boltpocket/expo-ssh`

Native SSH transport for BoltPocket's project-authorized SSH client commands. The
JavaScript surface exposes host-key probing, authenticated sessions, normal
POSIX path resolution from the login directory, bounded SFTP file operations,
and bounded non-interactive command execution. Remote path access is decided by
the authenticated server account, without an app-defined directory sandbox. It
never launches a platform shell, requests a PTY, or exposes an interactive
terminal.

## Native implementations

- Android uses a narrow JNI adapter over repository-built libssh2 `1.11.1` and
  statically linked OpenSSL `3.5.7` LTS. Every exported async transport
  operation runs on one module-owned coroutine queue, preserving call order
  for a session and keeping blocking network work off Expo's default queue.
  The JNI boundary accepts explicit UTF-8 byte arrays, returns bounded binary
  frames, verifies the exact native dependency versions at module startup, and
  clears password and private-key buffers. Module teardown cancels the scope,
  disconnects active sessions, and closes the dispatcher.
- iOS uses the pinned NMSSH Objective-C sources through the Expo module bridge.
  Every exported async transport operation runs directly on one serial dispatch
  queue, preserving the same per-session ordering as Android.
  NMSSH's bundled fat static libraries are intentionally not linked: their
  `arm64` slices are tagged for iOS devices and cannot be linked into an Apple
  Silicon simulator app. The config plugin instead installs checksum-pinned
  libssh2 and OpenSSL static XCFrameworks with separate `ios-arm64` and
  `ios-arm64_x86_64-simulator` slices.
- Expo autolinking is restricted to `BoltPocketSsh.podspec`; the helper podspecs are
  build dependencies, not Expo modules.

The iOS config is generated by `app.plugin.cjs`. Android packages checked-in
`jniLibs` from this module. Do not hand-edit or commit the generated `app/ios`
or `app/android` projects.

## Dependency status

Both platforms link repository-built libssh2 `1.11.1` against
checksum-pinned OpenSSL `3.5.7` LTS. OpenSSL 3.5 is supported upstream through
April 2030. The build keeps SHA-256 host-key pinning, password and in-memory key
authentication, bounded output/timeouts, and the existing JavaScript API.

Rebuild Android's checked-in `armeabi-v7a`, `arm64-v8a`, `x86`, and `x86_64`
libraries from the official source archives:

```sh
bash packages/expo-ssh/scripts/build-android-dependencies.sh
```

The script uses Android NDK `27.1.12297006` when available, targets API 24,
statically links crypto, and emits 16 KiB-aligned shared objects. Verify the
four artifacts and the absence of JSch with:

```sh
pnpm --filter @boltpocket/expo-ssh test
```

Rebuild the checked-in libssh2 XCFramework from its pinned upstream inputs:

```sh
bash packages/expo-ssh/scripts/build-ios-dependencies.sh
```

Both scripts verify every downloaded archive. The iOS build additionally fills
the incomplete upstream iOS header archive from the matching official OpenSSL
source release and builds `ios-arm64` plus
`ios-arm64_x86_64-simulator` slices. See `THIRD_PARTY_NOTICES.md` for licenses
and provenance.

## Verification

Verify Android packaging and Kotlin/Java compilation:

```sh
cd app/android
./gradlew :boltpocket-expo-ssh:assembleDebug :app:assembleDebug \
  -PreactNativeArchitectures=armeabi-v7a,arm64-v8a,x86,x86_64
```

With `PI_HOST`, `PI_PORT`, `PI_USER`, and `PI_PASSWD` exported from an
untracked credential source, the Android acceptance script configures a pinned
project profile through the UI and asks the real Agent to perform a read-only
diagnosis:

```sh
pnpm test:android-ssh -- --serial <non-Samsung-device> --metro-port 8081
```

After a clean Expo prebuild, verify both Apple targets:

```sh
pnpm --filter @boltpocket/mobile exec expo prebuild --platform ios --no-install
cd app/ios
pod install
xcodebuild -workspace BoltPocket.xcworkspace -scheme BoltPocket \
  -destination 'platform=iOS Simulator,name=<simulator>' build
xcodebuild -workspace BoltPocket.xcworkspace -scheme BoltPocket \
  -destination 'generic/platform=iOS' build
```

Do not disable code signing for either installed app artifact. BoltPocket relies on
Keychain entitlements for SecureStore-backed credentials, so an unsigned app
can launch while remaining unusable for authentication and real-model checks.
Use the Xcode project's configured signing identity for device builds.

For the simulator result, verify that the app executable reports both `arm64`
and platform `IOSSIMULATOR`; an Info.plist without the executable is not a
successful build.
